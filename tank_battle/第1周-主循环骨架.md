## 2. 你要用到的 pygame API（自己组织，本文不给成品代码）

| API | 干什么 | 关键点 |
|---|---|---|
| `pygame.init()` | 初始化所有子系统 | 应该在**循环外**、创建窗口前调用一次 |
| `pygame.display.set_mode((宽, 高))` | 创建窗口，返回一个 Surface（画布） | 参数必须是**一个元组**，写成两个参数会 `TypeError`；只调用一次，别放进循环 |
| `pygame.display.set_caption("坦克大战")` | 设置窗口标题 | 可选，但能让验收时一眼认出来 |
| `pygame.time.Clock()` | 创建时钟对象 | 循环外创建一次 |
| `clock.tick(60)` | 每帧调用，**把帧率限制在最多 60** | 返回距上一帧的毫秒数（先不用管）；放在循环**最后**；漏了它 CPU 会跑满 |
| `pygame.event.get()` | 取出「本帧发生的所有事件」的列表 | 每帧必须调用，否则窗口会变「未响应」 |
| `pygame.QUIT` | 事件类型：点了窗口右上角的 × | 用 `event.type == pygame.QUIT` 判断 |
| `screen.fill((R, G, B))` | 用纯色铺满整块画布 | 颜色是 0~255 的三元组；每帧开头清屏，否则会拖影 |
| `pygame.display.flip()` | 把画好的内容真正显示到屏幕上 | 每帧**只调用一次**，且要在所有绘制之后 |
| `clock.get_fps()` | 读当前帧率 | 用来做验收自检，验完可以删 |
| `pygame.quit()` | 退出 pygame、释放资源 | 循环**结束后**调用一次 |

> 提示：`pygame` 的官方文档 <https://www.pygame.org/docs/> 和 AI 都可以查，但**先自己试着拼**，
> 20 分钟拼不出来再问（需求文档 §11 的规则）。

## 3. 建议的实现顺序（每小步都留一个能跑的状态）

别一次写到底。按这个顺序，每步都能运行、都能看出对不对：

1. **开窗口**：`init()` → `set_mode()` → `set_caption()` → `pygame.quit()`。
   运行后窗口会一闪而过 —— 只要**终端不报错**就算这步过了。
2. **加循环**：加一个布尔变量（比如 `running = True`），`while running:` 里先只写
   `pygame.event.get()` 循环判断 QUIT，是就把 `running` 改成 `False`。
   运行后窗口能停住、点 × 能关掉 —— 这就是「关窗口干净退出」的雏形。
3. **加帧率**：循环里创建好的 clock 调 `tick(60)`。
   这步之后 CPU 占用会从跑满降下来（可以在任务管理器里对比看一眼，很直观）。
4. **加绘制**：循环里 `screen.fill(颜色)` + `pygame.display.flip()`。
   运行后窗口里是**纯色**，不再是灰白残影 —— 这就是「画面不闪」的基础。
5. **加自检**：临时加一段打印 `clock.get_fps()`（建议每 60 帧打印一次，别每帧都打）。
   验收完成后删掉这段，或者留着也无妨。

## 5. 常见坑（先在脑子里过一遍，能省半小时）

1. **忘了每帧调 `pygame.event.get()`** → 窗口标题栏出现「无响应」，点了 × 也关不掉。这是最常见的坑。
2. **参数忘了括号**：`set_mode((800, 600))` 是**一个元组**；写成 `set_mode(800, 600)` 直接 `TypeError`。
3. **忘了 `pygame.display.flip()`** → 窗口一直是灰/白，什么都没画上。
4. **`clock.tick(60)` 写在循环外面** → 帧率不受限，CPU 跑到 100%。
5. **`set_mode()` 写在循环里** → 每帧重建窗口，闪烁 + 越来越慢。
6. **没清屏**（`fill()` 在画东西之后，或干脆没写）→ 画面拖影。
7. **退出时只 `break` 不 `pygame.quit()`** → 大多数时候没事，但资源没释放不算「干净退出」。
   用 `while running:` + 循环后 `pygame.quit()` 是最稳的写法，不需要 `import sys`。
8. **终端里那行 `pygame 2.5.8 (SDL ...) Hello from the pygame community.`** → 是正常的欢迎横幅，**不是报错**。
9. **窗口标题用中文没问题**，但要确保 `main.py` 存成 UTF-8（VS Code 默认就是）。
10. **VS Code 按 F5 时提示「选择调试配置」** → 选 `Python File` 即可。它生成的 `.vscode/launch.json`
    正好被 `.gitignore` 里那条 `!.vscode/launch.json` 例外放行 —— 和上次 `settings.json` 同一个道理。

## 6. Git 动作

本条目**就在 `dev` 分支上提交**（切功能分支是条目 3 的事，别抢跑）。

分两次提交更清楚（也顺便多练一次 commit，凑需求文档那 20 次的目标）：

```powershell
# ① 先把这份指导文档入库（现在就能做）
git add "第1周-主循环骨架.md"
git commit -m "docs: 补充第 1 周条目 2 的操作指导"
git push

# ② 写完 main.py 并自测通过后，再提交代码
git status                                   # 看一眼待提交的东西
git add main.py
git commit -m "feat: 搭主循环骨架，事件-绘制-flip-tick 60"
git push                                     # 需求文档 §11：每次写完就 push，GitHub 就是备份

git log --oneline
```

- 提交信息用**半角冒号** `feat:`（英文 type 前缀：`feat` 功能 / `fix` 修 bug / `chore` 杂务 / `docs` 文档）。
- 想练「细拆提交」的话，可以把第 3 节的 5 个小步拆成 2~3 次 commit
  （比如「能开窗口并处理关闭事件」+「加帧率与绘制」），这也是需求文档第 15 项提倡的做法。
