## 3. 核心概念

### 3.1 命中判定：第一次用 `rect.colliderect`

条目 8 的碰撞是"**矩形 × 地图格子**"——因为地图是二维列表，只能自己算行列。这次两边都是矩形，pygame 直接给你一个方法：

```python
if bullet.rect.colliderect(enemy.rect):
    ...   # 两个矩形有重叠 → True
```

一行搞定，不用算行列、不用管 `-1` 边界。`colliderect` 只回答"**这两个矩形现在重叠吗**"，重叠了就是命中。

> 它和条目 8 手写的那套**不是一回事**：手写的 `collides_with_map(rect)` 负责"坦克/子弹 × 墙"，`colliderect` 负责"子弹 × 坦克"。两条线各管各的，别混。

### 3.2 谁打谁：靠"子弹在谁的列表里"，不用给 `Bullet` 加字段

直觉上会想给 `Bullet` 加个 `owner="player"` 之类的字段。**不用。** 条目 10 你让每辆坦克持有自己的 `bullets`，这个结构本身已经回答了"这颗子弹是谁的"：

| 遍历谁 | 得到什么 | 打中谁 |
|---|---|---|
| `tank.bullets` | 玩家的子弹 | 打**敌人** |
| `e.bullets` | 第 e 个敌人的子弹 | 打**玩家** |

于是规则表就定死了（**本条就按这个来，别自己加戏**）：

| 子弹来源 | 目标 | 结果 |
|---|---|---|
| 玩家 | 敌人 | 敌人消失，分数 +100，子弹消失 |
| 敌人 | 玩家 | 生命 −1，子弹消失 |
| 敌人 | 敌人 | **不判定**（互相穿过） |
| 玩家 | 玩家 | **不判定**（自己打不到自己） |

⚠️ 千万别写成一个"**所有子弹 × 所有坦克**"的双重大循环 —— 那样敌人会自己打自己、玩家会被自己的子弹打死，全是怪现象。

### 3.3 边遍历边删元素 = 本条最值钱的一课

命中之后要把敌人从 `enemies` 里删掉。**正着删会出事**：

```python
# ❌ 错的
for i in range(len(enemies)):
    if 命中了:
        enemies.pop(i)      # 删掉第 i 个之后，后面的元素全部前移一格
                            # 而 i 还在往前走 ⇒ 紧跟着的那个敌人被"跳过"、漏判
```

演示一下为什么：列表 `[A, B, C]`，`i=0` 时删掉 `A`，列表变成 `[B, C]`；下一轮 `i=1`，取到的是 `C` —— **`B` 被跳过了**。

两种正确写法，任选一种（本条的代码按第一种）：

```python
# ✅ 倒序遍历：从后往前删，前面的元素下标不受影响
for i in range(len(enemies) - 1, -1, -1):
    ...

# ✅ 遍历副本、改原表
for e in enemies[:]:        # [:] 复制一份，遍历的是副本
    enemies.remove(e)       # 删的是原表，副本不受影响
```

一句话记牢：**只要循环里会删元素，就得倒着来或者遍历副本。**

### 3.4 一发子弹只算一次命中

子弹 6px 宽、坦克 40px 宽，子弹速度 10px/帧 —— 一发子弹**会连续好几帧都压在敌人身上**。如果每帧都判一次，一个敌人会被打掉好几次、分数会连加好几次。

解决：**打中之后立刻把这颗子弹从列表里删掉**。子弹没了，下一帧自然不会再判到它。

```python
hit = None
for b in tank.bullets:
    if b.rect.colliderect(e.rect):
        hit = b
        break               # 一颗子弹打中一个就够了
if hit is not None:
    tank.bullets.remove(hit)
    enemies.remove(e)
    score += 100
```

⚠️ 注意这里**内层 `break`、外层再统一处理**的写法。如果写成"内层直接 `remove` 后继续循环"，外层如果用的是 `enemies[:]` 副本，同一颗子弹可能又打中另一个敌人（那颗子弹其实已经不在列表里了）。

### 3.5 分数与生命：模块级变量 + `global`

在 `tank = Tank(360, 280)` 附近加两个变量：

```python
score = 0        # 得分
lives = 3        # 剩余生命
```

然后写一个函数专门处理命中（放在 `enemies = [...]` 之后、主循环之前）：

```python
def handle_hits():
    """处理本帧的所有命中：玩家子弹打敌人、敌人子弹打玩家"""
    global score, lives                     # ← 关键，见下

    for e in enemies[:]:                    # 遍历副本
        hit = None
        for b in tank.bullets:
            if b.rect.colliderect(e.rect):
                hit = b
                break
        if hit is not None:
            tank.bullets.remove(hit)
            enemies.remove(e)
            e.bullets.clear()               # 它已经打出去的子弹也一并清掉
            score += 100

    for e in enemies:
        hit = None
        for b in e.bullets:
            if b.rect.colliderect(tank.rect):
                hit = b
                break
        if hit is not None:
            e.bullets.remove(hit)
            lives -= 1
```

**关于 `global`**：`score` / `lives` 是**模块级**变量（写在文件最外层）。函数里想**修改**它们，必须先写 `global score, lives` 声明一句。不写的话，`score += 100` 会被 Python 当成"在函数里新建一个局部变量 `score`"，然后因为"用的时候它还没赋值"而报错：

```
UnboundLocalError: cannot access local variable 'score' where it is not associated with a value
```

**只读不用声明，只写要声明。** 这个报错第一次见会很懵，记住这一条就不会踩。

### 3.6 插进主循环的位置

```python
    for e in enemies:
        e.maybe_turn(game_ticks)
        e.move(e.direction)
        e.check_collision(screen_rect)
        e.shoot(game_ticks)
        e.update_bullets()

    handle_hits()        # ← 必须放在所有 update_bullets() 之后
```

**为什么必须在 `update_bullets()` 之后**：`update_bullets()` 里子弹才刚移动过。如果先判命中再移动，判的是**上一帧的位置** —— 子弹明明已经飞过去了，却按旧位置算，表现就是"看着打中了却没反应"。

## 6. 踩过就懂的坑

1. **正序遍历列表、循环里 `pop` / `remove`** → 紧跟着的元素被跳过、漏判。**倒序遍历或遍历副本**（3.3）。
2. **命中后不删子弹** → 子弹压在敌人身上好几帧，每帧都判中：一个敌人被"打掉"多次、分数连加。**打中立刻移除那颗子弹**（3.4）。
3. **写成"所有子弹 × 所有坦克"的双重循环** → 敌人自己打自己、玩家被自己的子弹打死。**靠"子弹在谁的列表里"区分来源**（3.2）。
4. **先判命中、后 `update_bullets()`** → 判的是上一帧的位置，"看着打中了却没反应"。**判定必须在移动之后**（3.6）。
5. **函数里改 `score` / `lives` 忘了 `global`** → `UnboundLocalError: cannot access local variable 'score' ...`。**只读不用声明，只写要声明**（3.5）。
6. **敌人被打掉后，它已经打出去的子弹还留在内存里** → 这些子弹不再被更新（绘制循环遍历的是 `enemies`，它已经不在里面了），不会动也不会画，但白占内存。**`e.bullets.clear()` 一并清掉**。
7. **给 `Bullet` 加 `owner` 字段** → 能跑，但本条根本不需要：`tank.bullets` 和 `e.bullets` 已经天然分开了。多一个字段就多一处要同步维护的地方。（条目 13 重开一局时才需要小心地把所有列表清干净。）
8. **`lives` 掉到 0 之后继续玩** → 本条**故意不处理**，游戏结束/结算画面是条目 13 的事。现在掉成负数也没关系，别提前把结算逻辑塞进来。
9. **`print` 每帧都打** → 一秒钟刷 60 行，真正要看的变化被冲掉。**只在 `score` / `lives` 变化时打印**（3.7）。
10. **一发子弹同时重叠两个敌人时，两个都被打掉** → 如果内层不 `break`、或者外层用了副本还继续判，同一颗子弹可能"打掉"两个敌人。**内层 `break`、外层统一处理**（3.4）。
