## 3. 核心概念

### 3.1 ⭐ 重构的验收标准是"行为不变"

这是本条最重要的一句话，值得放最前面。

加功能时，验收标准是"该出现的东西出现了没"。**重构时没这回事** —— 重构的定义就是"不改行为，只改结构"。所以验收标准只能是：

> **拆之前玩游戏和拆之后玩游戏，每一步的状态都一模一样。**

怎么"一模一样"？你得能**把两个版本并排跑，逐帧对比**。我在探针里就是这么干的（`split_verify.py`）：同一套脚本化按键喂给两边，每帧抓 11 项状态对比 —— 分数、生命、敌人坐标、砖墙数、钢墙数、游戏状态、结算文字、玩家坐标、双方子弹坐标。

三套脚本全过：

| 脚本 | 内容 | 帧数 | 结果 |
|---|---|---|---|
| A | 上左下右移动 + 两次空格（其中一次在冷却里，应被拒） | 80 帧 | 11 项 × 80 帧**完全一致** |
| B | 把玩家钉在敌人炮口下挨打 → 第 37 帧结算 → 按 R 重开 → 再玩 | 82 帧 | 完全一致 |
| C | 第 12 帧清空敌人 → 胜利结算 → 按 R | 40 帧 | 完全一致 |

三个场景覆盖了"普通移动""死亡结算重开""胜利结算重开"三条主要路径。

**你不需要自己写这套对比工具** —— 那是我干的活。但你要知道**为什么拆完必须这样验**，因为拆模块最容易出的错（漏了个 `import`、变量绑错了对象）**平时玩两下根本看不出来，但一到特定场景就炸**。

### 3.2 谁 `import` 谁：依赖只能**单向往下**

拆文件最核心的问题：**A 文件要用 B 文件的东西，就 `import` B**。但要是 B 又反过来 `import` A，Python 会直接报错（`ImportError` / `cannot import name ... from partially initialized module`）—— 这叫**循环导入**。

所以拆之前，先画一张"谁用谁"的图。**箭头只能朝一个方向，不能有环**：

```
   main.py
      │
      ▼
   game.py ──────┐
      │          │
      ▼          ▼
   tank.py ──▶ bullet.py
      │          │
      ▼          ▼
   map.py ───────┘
      │
      ▼
   settings.py
```

翻译成 import 语句（**这就是成品里的实际写法，可以直接抄**）：

```python
# settings.py —— 只依赖 pygame
import pygame

# map.py —— 依赖 settings
import pygame
from settings import TILE_SIZE, COLORS

# bullet.py —— 依赖 settings、map
import pygame
from settings import DIR_VECTORS, TILE_SIZE, COLORS
from map import MAP_DATA, MAP_ROWS, MAP_COLS

# tank.py —— 依赖 settings、map、bullet
import pygame
import random
from settings import DIR_NAMES, DIR_VECTORS, TILE_SIZE, COLORS, SHOT_COOLDOWN
from settings import SCREEN_WIDTH, SCREEN_HEIGHT
from map import collides_with_map
from bullet import Bullet

# game.py —— 依赖 settings、map、tank、bullet
import pygame
from settings import KEY_TO_DIR, DIR_KEYS, COLORS, SCREEN_WIDTH, SCREEN_HEIGHT, HUD_COLOR
from map import MAP_DATA, MAP_1, draw_map
from tank import Tank, Enemy_Tank
from bullet import Bullet

# main.py —— 只依赖 game
from game import run
```

几个"为什么这么分"的点：

- **`map.py` 不 import `tank.py`** —— 虽然碰撞检测是坦克在调，但 `collides_with_map(rect)` 只收一个矩形，它不需要知道"矩形来自坦克"。
- **`tank.py` import `bullet.py`** —— 因为 `Tank.move_shoot` 时要 `Bullet(self.rect, self.direction)` 造子弹。
- **`bullet.py` 不 import `tank.py`** —— 子弹只收一个 `tank_rect`（一个 `pygame.Rect`），也不需要知道那是谁。
- **`game.py` 在最上面** —— 只有它 import 别人，没有别人 import 它。这是有意的：**你能不能独立 `import` 一个模块**，是判断拆得好不好的最快方法。

> 💡 **`import` 里没用到的东西要删掉**。比如 `bullet.py` 里 `is_off_screen(screen_width, screen_height)` 的尺寸是**当参数传进来的**，所以它其实不需要 `from settings import SCREEN_WIDTH, SCREEN_HEIGHT`。多 import 不报错，但读代码的人会以为这里用得到。

### 3.3 ⭐⭐ `MAP_DATA` 跨文件之后会变成一颗地雷

这条是本条**最危险**的地方，也是条目 13 结尾我特意提过的。

先复习条目 13 学到的东西：`MAP_DATA` 是**可变的游戏状态**（子弹打砖墙会把它改成 0），恢复时必须用**切片赋值** `MAP_DATA[:] = ...`，**不能重新赋值** `MAP_DATA = ...`。当时的理由是"别处缓存的引用还指着旧列表"。

**拆成模块之后，这个理由从"理论上的"变成"天天会踩的"** —— 因为现在有**两个文件**同时持有这个列表：

```
map.py     ← MAP_DATA 定义在这里
bullet.py  ← from map import MAP_DATA   ← 拿到了同一个列表
game.py    ← from map import MAP_DATA   ← 又拿到同一个列表
```

**情况一：改元素（正确写法，两边同步）** ✅

```python
# bullet.py 里，子弹打中砖墙
MAP_DATA[row][col] = 0
```

`MAP_DATA` 这个名字在 `map.py` / `bullet.py` / `game.py` 里**指向的是同一个列表对象**（实测：`bullet.MAP_DATA is map.MAP_DATA` → `True`，两个 id 完全相同）。所以改一格，三个文件全都看得到。**这就是你要的效果。**

**情况二：重新赋值（炸了）** ❌

```python
# game.py 里，重开一局时
MAP_DATA = [row[:] for row in MAP_1]    # ← 灾难
```

这行**不会**报错，但会发生这件事：**`game.py` 里的 `MAP_DATA` 现在指着一个新列表，而 `map.py` 和 `bullet.py` 里的 `MAP_DATA` 还指着旧的那个。**

后果是**幽灵 bug**：

- `draw_map()` 画的是 —— 嗯，`draw_map` 在 `map.py` 里，它看的是**旧列表**（打烂的地图）→ **画出来还是破的**。
- `bullet.hit_wall()` 改的是 `bullet.py` 里的那个，也是**旧列表** → 子弹打在旧地图上。
- 而你 `print(MAP_DATA)` 看的是 `game.py` 里的**新列表** → **一切正常，看不出问题**。

**"画出来是破的、打起来是破的、打印出来是好的"** —— 这就是幽灵 bug 的样子，能查你一晚上。

**正确写法（条目 13 已经这么写了，别改）**：

```python
# game.py 里，reset_game() 内部
MAP_DATA[:] = [row[:] for row in MAP_1]   # 切片赋值：改的是"列表里的内容"，不是"这个名字指向谁"
```

切片赋值动的是**列表本身**，三个文件看到的还是同一个对象，所以全都同步还原。**实测：连玩三局，`MAP_DATA` 的 id 从头到尾没变过（`0x1d87a9f6880` → 一直是它）。**

**一句话记住**：`import` 时拿到的是**对象的引用**。改内容（`[i][j] = x`、`[:] = ...`）全文件同步；改名字（`MAP_DATA = ...`）只改自己那一个文件。

### 3.4 主循环要包进 `def run()`

拆文件之后，`main.py` 只剩几行：

```python
from game import run

if __name__ == "__main__":
    run()
```

**这意味着主循环不能再裸着放在模块里** —— 不然 `main.py` 一 `import game`，游戏当场就跑起来了，`from game import run` 这行还没执行完呢。所以主循环必须**包成一个函数**：

```python
def run():
    """主循环：一直跑，直到窗口被关掉或按了 Ctrl+W"""
    global running
    running = True
    while running:
        ...          # ← 原来主循环的整段代码，整体缩进 4 格
    pygame.quit()
```

**唯一需要改的代码就是它** —— 主循环整段缩进 4 格，然后把末尾的 `pygame.quit()` 挪进来当最后一行。**别的一个字都不用动。**

顺带解释 `if __name__ == "__main__":` 这行是干什么的：

- 直接跑 `python main.py` 时，Python 给这个文件的 `__name__` 赋值 `"__main__"` → 条件成立 → `run()` 执行。
- 别的文件 `import main` 时，`__name__` 是 `"main"` → 条件不成立 → **不会启动游戏**。

这是 Python 的标准写法，好处是 `main.py` 变得可以被安全地 import（比如以后写测试时）。

### 3.5 `pygame.init()` 之类的"开机动作"放哪

模块拆开之后，有一类代码很尴尬：`pygame.init()`、`pygame.display.set_mode(...)`、`pygame.font.Font(...)`、`clock = pygame.time.Clock()` —— 它们**必须执行一次**，但又不属于任何"东西"。

规则：**都放 `game.py`，而且放在模块级**（就是现在的位置），别放进 `run()`。

理由：

- **放模块级**：`import game` 时就初始化好了。字体对象只建一次（条目 12 的性能要点 ✅）。
- **放进 `run()`**：`run()` 每被调一次就重建一遍。现在只调一次，无所谓，但这是坏习惯。

**注意顺序问题**：`OVERLAY = pygame.Surface(...)` **必须**在 `pygame.display.set_mode(...)` 之后。拆文件时这个顺序别打乱（条目 13 的坑 6）。

### 3.6 ⚠️ 一个坑：`game.py` 在 `import` 时就会建 `clock`

这条是我在探针里**真踩到**的，写出来给你省时间。

既然 `game.py` 在模块级写了 `clock = pygame.time.Clock()`，那 **`import game` 这个动作本身就会创建一个 Clock 对象**。平时无所谓，但如果你以后写测试、想替换掉这个时钟（我的探针就要替换它来跑快进），会发现：**光在 `import game` 之前把 `pygame.time.Clock` 换掉还不够 —— 已经 import 过的 `game` 模块里那个 clock 是老的。**

解决办法是 `del sys.modules["game"]` 强制重新 import。**平时写游戏用不到这个知识**，先记着有这么回事就行。

`run()` 的开头固定这么写：

```python
def run():
    """主循环：一直跑，直到窗口被关掉或按了 Ctrl+W"""
    global running
    running = True
    while running:
        ...
```

> **关于第 5 步的"照原顺序搬"**：原来 `main.py` 里的顺序是 `tank` / `score` / `lives` / `enemies` / `game_state` / 文字 / `running = True`（main.py:351-363）。这个顺序不影响运行（都是简单赋值），但**原样搬过去**以后回头对比两版代码时最省事 —— 重构的原则就是"除了位置，什么都没变"。

> `global running` 是必须的 —— 事件处理里要写 `running = False`，不加 `global` 会**静默失效**（条目 13 坑 4 的同款）。顺带一提，主循环内部本来就要读 `tank` / `enemies` / `score` / `lives` / `game_state`，它调用的那些函数里**已经有各自的 `global` 声明**了，所以别的地方不用加。

## 6. 踩过就懂的坑

1. **忘写某个 `import`** → 一运行就 `NameError: name 'KEY_TO_DIR' is not defined`。**这是拆模块最常见的错，我在探针里第一跑就撞上了**（`game.py` 漏了 `KEY_TO_DIR`）。好消息是报错信息会直接告诉你缺哪个名字，补上就行。
2. **漏掉 `import random`** → `NameError: name 'random' is not defined`，而且**只有敌人转向时才炸**（`random.choice` 在 `Enemy_Tank` 里）。搬 `tank.py` 时特别容易漏。
3. **忘了 `import pygame`** → 每个用到 pygame 的文件都要自己 import 一次。**别指望"别的文件 import 过了"** —— `import` 是每个文件各自的事。
4. **⭐ 在 `game.py` 里写 `MAP_DATA = [...]`** → 幽灵 bug：**画出来是旧的、打起来是旧的、你 print 出来是新的**（§3.3）。**必须切片赋值 `MAP_DATA[:] = ...`**。
5. **反向 import（循环导入）** → `ImportError: cannot import name 'X' from partially initialized module`。**依赖只能单向往下**（§3.2 那张图）。
6. **主循环没包进 `def run()`** → `main.py` 一 `import game`，游戏当场就跑起来，卡在那儿不返回。
7. **主循环包了但忘了缩进 4 格** → 一运行就 `IndentationError`。整段选中按 `Tab` 最省事。
8. **`pygame.quit()` 忘了从 `main.py` 挪进 `run()`** → 它会在 `import` 时就被执行、把 pygame 关掉，然后 `run()` 里什么都跑不了。
9. **`run()` 里漏了 `global running`** → 事件里 `running = False` **静默失效**，关不掉窗口。**不报错**，最难查。
10. **把 `pygame.init()` / `set_mode` / 字体 挪进了 `run()`** → 能跑，但字体每调一次 `run()` 就重建一遍（条目 12 的性能要点）。**放模块级。**
11. **`OVERLAY` 挪到 `set_mode` 之前** → `error: No convert format has been set, try display.set_mode()`（条目 13 坑 6 同款）。
12. **常量"顺手"也定义了一份在别的文件** → 两处不一致时，改了一处另一处不变。**常量只在 `settings.py` 定义，别处只 `from settings import`。**
13. **把 `settings.py` 写成了"杂物间"** → 函数、类、游戏状态全往里塞。**它只放常量**，连 `MAP_DATA` 都不该放（那是可变状态，属于 `map.py`）。
14. **`from map import MAP_DATA` 之后以为拿到了"副本"** → 不是副本，是**同一个列表**（实测 `is` 为 `True`）。这正合你意（改一处全同步），但要知道它不是拷贝 —— 想真拷贝得 `[row[:] for row in MAP_DATA]`。
15. **拆完发现某文件"什么都沾一点"** → 说明切错了。回头看 §2 那张表：每个文件的职责能用**一句话**说清才是对的。
16. **合并回 `dev` 前忘了 `git pull`** → `dev` 上若有新提交可能撞冲突。撞了就按 `第2周-合入主线.md` 的流程走。
17. **拆分时"顺手改点别的"** → 重构的第一原则是**不夹带**。想调速度、想改颜色，留到条目 15。夹带了，一旦行为变了，你分不清是"拆错了"还是"改错了"。
18. **以为"拆完看不出区别"是没成功** → 恰恰相反。**重构成功的标志就是看不出区别**（§3.1）。
