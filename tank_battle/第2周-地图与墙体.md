## 3. 本条要学的新概念

### 3.1 二维列表 = 列表的列表

地图数据就是一个**「行的列表」，每行又是「格子的列表」**：

```python
MAP_DATA = [
    [2, 2, 2, 2, 2],   # 第 0 行
    [2, 0, 0, 1, 2],   # 第 1 行
    [2, 1, 0, 0, 2],   # 第 2 行
]
```

取值是 `MAP_DATA[行][列]` —— ⚠️ **先写行、后写列**，跟你直觉里的 `(x, y)` **正好相反**。
这是本条最容易搞反的地方：写反了画面会整体转置（甚至 `IndexError`）。

### 3.2 格子坐标 → 像素坐标

屏幕不认识"第 3 行第 5 列"，只认像素。所以：

```
像素 x = 列号 × 格子边长
像素 y = 行号 × 格子边长
```

**格子边长建议 `TILE = 40`** —— 和坦克一样大，一车一格，正好：

| | 计算 | 结果 |
|---|---|---|
| 列数 | 800 ÷ 40 | **20 列** |
| 行数 | 600 ÷ 40 | **15 行** |

也就是一份 **15 行 × 20 列** 的二维列表。多一列少一行都会让墙跑出屏幕或留黑边。

### 3.3 数据驱动画面（本条的真正重点）

**画面长什么样，由数据决定，不由代码决定。**

这条思路一旦建立，以后"多关卡"（需求文档 §5.2 的迭代项）就是**换一份 `MAP_DATA`**，代码一行都不用改。
你要练的不是"怎么画墙"，而是"**怎么让数据说了算**"。

## 4. 你要用到的 API / 写法

| 用什么 | 干什么 | 关键点 |
|---|---|---|
| `MAP_DATA = [[...], [...]]` | 存地图数据 | 0 空 / 1 砖墙 / 2 铁墙；**15 行 × 20 列** |
| `TILE = 40` | 格子边长常量 | 放 `COLORS` 旁边，别散落在代码里 |
| `enumerate(列表)` | 同时拿到**下标**和**元素** | `for row, line in enumerate(MAP_DATA)` 一行拿到行号和整行 |
| 嵌套 `for` | 逐格遍历 | 外层走行、内层走列 |
| `pygame.draw.rect` | 画每个墙块 | 你已经很熟了 |
| `COLORS["brick"]` / `COLORS["steel"]` | 两种墙的颜色 | 往你现有的 `COLORS` 字典里加键即可 |

> **可选加分**：地图用**字符串**写更好读、更不容易数错格子 ——
> ```python
> MAP_ROWS = [
>     "22222222222222222222",
>     "20000000000000000002",
>     ...
> ]
> ```
> 再写几行代码把它转成数字列表（`"2"` → `2`）。手写 300 个数字很容易漏一个，
> 而**漏了不会报错**，只会在画面角落少一块墙（见"常见坑"第 5 条）。

## 5. 实现顺序（每步都留一个能跑的状态）

1. **先写一份小地图试水**：别一上来就写 15×20。先写 **5 行 × 8 列**，四周一圈 `2`、里面随便点几个 `1`。
   配合渲染代码跑通，确认"格子 → 像素"的换算是对的。
2. **写渲染函数**：一个独立函数（比如 `draw_map(surface)`），嵌套循环 + 按值选颜色画矩形。
   接到主循环里：`fill` 之后、`tank.draw` 之前。
3. **把地图扩到满屏**：改成 15 行 × 20 列。
4. **给坦克留出生点**：坦克出生在 `(380, 280)` —— 那是**第 7 行第 9 列**（380÷40=9.5，280÷40=7）。
   确认那一格是 `0`，否则坦克一出生就卡在墙里。
5. **验"数据驱动"**：随手把某个 `1` 改成 `0`，重跑 —— 那块墙应该消失。

## 7. 常见坑（按踩中概率排序）

1. **行列写反**：写成 `MAP_DATA[列][行]` → 画面整体转置，或直接 `IndexError: list index out of range`。**记住是 `[行][列]`**。
2. **遍历时变量名撞车**：`for i in MAP_DATA: for i in i:` —— 内层把外层变量覆盖了。用 `row` / `col` 或 `row` / `line` 这种分得开的名字。
3. **忘了乘 `TILE`**：直接拿行号列号当像素坐标 → 所有墙挤在左上角一小块。
4. **地图尺寸和窗口对不上**：20 列 × 40 = 800 ✓；写成 21 列就超出屏幕，19 列就右边留黑边。行数同理（15 行 = 600）。
5. **⚠️ 每行长度不一致**：手写二维列表最容易犯，而且**不会报错** —— 只会让画面某行缺一块墙。
   对策：要么用字符串写法，要么写完先打印一下每行的 `len()` 核对。
6. **坦克出生在墙里**：出生点 `(380, 280)` 对应第 7 行第 9 列，把那一格留成 `0`。
7. **画墙的位置不对**：必须在 `screen.fill(...)` **之后**画，否则被背景盖掉（顺序：fill → 地图 → 坦克）。
8. **把墙画在坦克之后** → 坦克走进墙里时会被墙盖住看不见（本条不做碰撞，所以"穿墙"是预期的，但至少别让坦克消失）。
9. **每帧重建地图数据** → 没必要；`MAP_DATA` 是常量，定义在文件顶部就行。
10. **性能顾虑**：每帧画 300 个矩形完全没问题。但记住这个思路 —— 等地图变得很大（比如 100×100）时，
    可以把地图**预渲染到一张 `Surface`** 上，每帧只 `blit` 一次。现在不用做，知道有这么条路就行。
