## 3. 本条的核心：⚠️ 别在遍历列表时删元素

这是 **Python 最经典的坑之一**，而且它**不报错**、只是悄悄漏掉一半。先亲手看一遍：

```python
# 拿 6 个数模拟 6 颗待销毁的子弹
nums = [1, 2, 3, 4, 5, 6]
for n in nums:
    nums.remove(n)          # 边遍历边删
print(nums)                 # 你以为 []，实际 [2, 4, 6]
```

**为什么？** `for` 循环靠一个内部计数器记住"现在读到第几个"：

| 轮次 | 计数器 | 读到 | 删除后列表变成 | 下一轮读到 |
|---|---|---|---|---|
| 1 | 0 | `1` | `[2,3,4,5,6]` | 索引 1 → `3`（**2 被跳过了！**） |
| 2 | 1 | `3` | `[2,4,5,6]` | 索引 2 → `5`（**4 被跳过**） |
| 3 | 2 | `5` | `[2,4,6]` | 索引 3 → 越界，结束 |

**删一个，列表就短一格，但计数器照常 +1 —— 于是下一个元素被跳过。**
要删 6 个，结果只删掉 3 个。

> 你可以把上面 4 行抄进一个临时 `.py` 跑一下，**亲眼看到 `[2, 4, 6]`**，比读十遍解释都管用。

对应到你的代码，**错误写法**是：

```python
for bullet in bullets:
    bullet.bullet_move()
    if 飞出屏幕:
        bullets.remove(bullet)      # ❌ 漏删一半，而且子弹越多漏得越多
```

## 4. 三种正确写法（选一个）

### 写法 A：列表推导式重建（最 Pythonic，推荐）

```python
bullets = [b for b in bullets if not 出界(b)]
```

**一行搞定**：只留下"还在屏幕内"的子弹。这条语法本身就是 Python 的招牌之一（顺便也是需求文档 §2.1 里"列表"这项学习目标的实战）。

### 写法 B：倒着遍历删

```python
for i in range(len(bullets) - 1, -1, -1):
    if 出界(bullets[i]):
        bullets.pop(i)
```

**为什么倒着就安全？** 因为删除位置**之后**的元素才会移位，而你正在往**前**走 —— 前面已经处理过的部分不受影响。

### 写法 C：收集存活的，最后替换

```python
alive = []
for b in bullets:
    if not 出界(b):
        alive.append(b)
bullets = alive
```

最直白，但比写法 A 多几行。

> **写法 A 有个细节**：`bullets = [...]` 让 `bullets` 指向**一个新列表**。
> 如果你别处还留着旧列表的引用（比如传给了某个函数），那边看不到更新。
> 你现在是全局一个 `bullets`，所以没问题。想避免这个隐患可以用
> `bullets[:] = [...]`（**原地**替换内容，对象不变）。

## 5. 出界怎么判断？

### 推荐：用 `Rect.colliderect`（一行，还顺便预习条目 8）

```python
screen_rect = screen.get_rect()
if not screen_rect.colliderect(bullet.rect):
    # 和屏幕完全不重叠 = 已经飞出屏幕
```

`colliderect` 判断"两个矩形是否相交" —— 这正是**条目 8 碰撞检测**要用的 API，这里先热个身。

### 也可以：四个方向手写

```python
if (b.rect.right < 0 or b.rect.left > W or
    b.rect.bottom < 0 or b.rect.top > H):
```

### ⚠️ 关键：判据要用「**完全飞出**」，不能用「**碰到边缘**」

如果你写成 `if b.rect.x < 0:` —— 那么**坦克贴着左边界朝左开火时，子弹一出生 `x` 就是负的**（你的出生点是 `tank_rect.left - 6`），于是子弹**当场被销毁**，表现为"贴着墙打不出子弹"。

**必须用 `right < 0` / `left > W` / `bottom < 0` / `top > H`**（整个矩形都跑到屏幕外了才算），也就是"完全飞出"。用 `colliderect` 的写法天然就是对的。

## 6. 实现顺序

1. **先加出界判断、打印列表长度**：在循环里临时加一行 `print(len(bullets))`（或者每 30 帧打一次，别每帧都打）。
2. **按写法 A/B/C 之一加销毁逻辑**：位置放在「子弹移动之后、绘制之前」。
3. **观察数字**：朝天空打 10 发，看 `len(bullets)` 是不是**涨上去又落回 0**。
   - 如果**只涨不落** → 判据写错了（可能用了 `x < 0` 之外的问题）或者根本没执行到。
   - 如果**落得很慢** → 判据太宽松（比如用了 `right < -100`）。
4. **四方向各打几发**：确认每个方向飞出去的都能被销毁（别只顾着上下）。
5. **压力测试**：连打 100 发（按住空格放一会儿就行），看列表长度是否**始终保持在个位数**、帧率是否稳。
6. **删掉临时打印**（或留着也行，但发布前记得清理）。

## 9. 常见坑（按踩中概率排序）

1. **在 `for bullet in bullets:` 里 `bullets.remove(bullet)`** → 漏删一半（本节开头那个实验）。**本条的头号坑。**
2. **判据用了"碰到边缘"而不是"完全飞出"**（`x < 0` 而非 `right < 0`）→ 坦克贴边开火时子弹出生即死，表现为"打不出子弹"。
3. **判据方向写漏**：只判了上下、忘了左右 → 横向飞出的子弹永远留在列表里（列表长度缓慢上涨，很难发现）。
4. **销毁逻辑写在绘制之后** → 当帧已经画过了（无所谓），但更常见的问题是写在了 `for` 循环**外面**且用错了索引。
5. **用 `del bullets[i]` 但 `i` 来自遍历** → 和 `remove` 一样的错位问题。
6. **销毁条件写反**：`if screen_rect.colliderect(b.rect): 销毁` → 把**屏幕上**的子弹全删了，表现为"子弹一闪就没了"。
7. **列表长度不回落但你没发现** → 因为子弹飞出屏幕后**看不见**，画面完全正常。**这就是为什么需求文档要用"列表长度"当验收标志，而不是靠肉眼。** 一定要打印或让探针数。
8. **别忘了**：Python 会自动回收内存，你**只需要把对象从列表里移除**，不需要手动 `del` 或 `free`。但如果别处还留着引用，它就回收不掉 —— 现在只有一个列表，不涉及。
9. **性能误区**：不要为了"省内存"每帧重建整个列表 —— 列表推导式写法 A 看着像"重建"，实际开销极小（几十个元素），**不要为此写复杂代码**。
