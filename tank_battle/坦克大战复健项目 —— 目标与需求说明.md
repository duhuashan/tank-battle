# 坦克大战复健项目 —— 目标与需求说明

## 1. 背景与动机

很久以前跟着网上教程做过一个坦克大战小游戏，但源文件已丢失，Python 也生疏了。现在想通过重做这个项目，恢复代码手感，同时学会用 Git/GitHub 管理项目。

## 2. 目标

### 2.1 学习目标

- 恢复 Python 基础：函数、类、列表、字典、文件读写、异常处理。
- 掌握 pygame 基本用法：窗口、事件、绘制、碰撞。
- 能独立组织一个 300 行以上的小项目。

### 2.2 工程目标

- 用 Git 管理每次修改，养成提交习惯。
- 用 GitHub 托管仓库，学会 Issue、分支、合并、Release。
- 最终发布一个可运行版本 v0.1.0。

### 2.3 产品目标

- 做一个能玩的坦克大战 MVP：移动、射击、敌人、碰撞、分数、游戏结束。

## 3. 非目标（明确不做什么）

- 不做联网对战。
- 不做复杂关卡编辑器。
- 不追求精美美术和音效。
- 不学 Web、数据分析、AI 等其他方向。
- 不追求一次写完，允许代码丑，先跑起来。

## 4. 用户与场景

- **用户**：我自己。
- **场景**：本地运行，键盘操作，单机游戏。

## 5. 功能需求

### 5.1 MVP（必须完成）

- 游戏窗口和主循环。
- 玩家坦克：上下左右移动，边界限制。
- 子弹：空格发射，飞行，出界消失。
- 敌人坦克：随机移动，简单开火。
- 碰撞：子弹打坦克、子弹打墙、坦克撞墙。
- 分数与游戏结束。
- 重新开始。

### 5.2 迭代（有时间再做）

- 多关卡。
- 音效。
- 开始菜单。
- 简单存档。
- 敌人 AI 改进。

## 6. 技术选型

- Python 3.12+
- pygame
- VS Code
- Git + GitHub

## 7. Git/GitHub 练习目标

- 初始化仓库，写 `.gitignore`。
- 每次完成一个小功能就 commit，信息写清楚。
- 建 dev 分支和功能分支，练习合并。
- 用 Issues 记录待办和 bug。
- 打标签 v0.1.0，发一个 GitHub Release。
- 写 README.md，说明怎么运行。

## 9. 执行计划表

节奏建议：每天至少 30 分钟，周末补齐；单个条目卡住超过 20 分钟就查文档或问 AI，不硬耗。每周末留 20 分钟整理 commit、更新 Issues。

提交数提醒：下表 18 个条目各对应 1 次以上 commit，但离验收要求的 20 次还差一点——手感调试（第 15 项）和边界 bug 修复天然适合拆细提交，边调边提交就够了，不要为了凑数造空提交。

## 10. 验收标准

- 游戏能正常运行，核心玩法完整。
- GitHub 上有仓库，有 README 和至少一个 Release。
- 我能不看教程写出主循环和类结构。
- 至少完成 20 次有意义的 Git 提交。

## 13. 附录：写这类文档的小技巧

- 放在项目根目录，命名 `README.md` 或 `docs/需求说明.md`。
- 先写目标、非目标、MVP 功能、验收标准，这四块最重要。
- 不用一次写完美，随着项目进展更新。
- Git 提交时可以把这份文档一起提交，本身就是练习。
