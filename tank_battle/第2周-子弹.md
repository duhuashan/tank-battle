## 3. 新概念：游戏对象的列表

到现在为止，场上只有**一个**坦克，代码里就一个变量 `tank`。子弹不一样 —— 你连按几次空格，屏幕上就会有好几颗子弹同时在飞。

所以子弹不能用一个变量存，要用**列表**：

```
bullets = []          # 空列表 = 场上没有子弹
bullets.append(Bullet(...))     # 发射 = 往列表里加一个
for b in bullets:               # 每帧：逐个更新、逐个画
    b.update()
    b.draw(screen)
```

**这个"列表 + 逐帧遍历"的模式，是几乎所有游戏的核心结构。** 以后敌人、爆炸特效、道具，全都是这个套路。

## 4. 设计要点（自己定，本文不给成品代码）

### 4.1 `Bullet` 类要哪些属性？

| 属性 | 说明 |
|---|---|
| `rect` | 位置 + 尺寸。建议小一点（比如 **8×8** 或 **6×6**），比坦克小一圈才像子弹 |
| `direction` | 飞行方向，**直接沿用坦克那套字符串** `"UP"/"DOWN"/"LEFT"/"RIGHT"` |
| `speed` | 飞行速度。**必须比坦克快** —— 坦克是 `5`，子弹建议 **10~15** |

### 4.2 子弹从哪出生？（这一步的观感关键）

**不要从坦克中心出生。** 坦克 40×40，炮管朝那一侧伸出约 11 像素 —— 子弹应该从**坦克朝向那一侧的边缘**（甚至再往外一点）冒出来，看起来才像"从炮口射出去"。

用 `self.rect` 的现成属性定位最省事：`centerx` / `centery` / `top` / `bottom` / `left` / `right`。

### 4.3 方向怎么变成位移？

你有两种写法，**选一个并说得出理由**：

| 写法 | 样子 | 取舍 |
|---|---|---|
| `if/elif` 四分支 | 和 `Tank.tank_move` 一样 | 直观，但四方向就要写四遍 |
| **方向字典**（推荐） | `DIR_VECTORS = {"UP": (0, -1), "DOWN": (0, 1), "LEFT": (-1, 0), "RIGHT": (1, 0)}` | 一行搞定位移：`dx, dy = DIR_VECTORS[self.direction]`，然后 `rect.x += dx * speed` |

字典写法还有个好处：**以后想让坦克也用它，`Tank.tank_move` 那 12 行 `if/elif` 能压成 3 行**（这属于加分项，本条不必做）。

> ⚠️ 记住 y 轴向下：`"UP"` 对应 `(0, -1)`，负号别丢。

### 4.4 开火冷却：本条的核心考点

需求文档明确要求"**连按空格受冷却限制，不会刷屏**"。为什么非做不可？有两个原因：

**原因一**：玩家手速很快，一秒能按 10 次。
**原因二（更隐蔽）**：**按住空格不放时，操作系统会以每秒约 30 次的速率重复发送 `KEYDOWN` 事件** ——
所以就算你只在 `KEYDOWN` 里发射、且玩家只是"按住"，子弹也会像机关枪一样喷出来。

两种实现方式：

| 做法 | 怎么写 | 取舍 |
|---|---|---|
| **时间戳**（推荐） | 记一个 `last_shot`（毫秒），发射前比较 `pygame.time.get_ticks() - last_shot >= COOLDOWN` | 冷却时间**精确到毫秒**，不受帧率影响 |
| 帧计数 | 记 `cooldown_timer`，每帧减 1，到 0 才能发射 | 简单，但冷却时长**随帧率变**（掉帧时冷却变长） |

建议 `COOLDOWN = 250 ~ 400`（毫秒）—— 大约每秒 3 发，手感合适。

**冷却状态放哪？** 两个选择：
- 放**坦克**身上（`self.last_shot`）—— 更面向对象：**"谁能开火"是坦克的事**
- 放**全局变量** —— 简单，但以后有敌人坦克时就得再复制一份

想清楚再写。这个选择在条目 10（敌人也要开火）时会显出差别。

### 4.5 按键：`KEYDOWN` 还是 `get_pressed`？

| | 行为 | 适合 |
|---|---|---|
| `KEYDOWN` 事件 | 按下那**一瞬间**触发一次 | **发射**（本条的推荐，配合冷却） |
| `key.get_pressed()` | 只要按住，**每帧**都为真 | 持续动作（如移动） |

你现在移动用的是 `pressed_order`（基于 KEYDOWN/KEYUP），退出用的是 `get_pressed()`。
发射建议用 **KEYDOWN + 冷却** —— 语义最清楚：**"按一下 = 想开一炮"**。

## 5. 实现顺序（每步都留一个能跑的状态）

1. **先写 `Bullet` 类 + 一个写死的子弹**：在循环外手动 `bullets = [Bullet(400, 300, "UP")]`，
   让 `update()` 每帧往上飞、`draw()` 画个小方块。跑一下 —— 看它飞出去（飞出屏幕也别管）。
2. **接上空格发射**：`KEYDOWN` + `K_SPACE` → `bullets.append(Bullet(...))`，出生点取坦克边缘、方向取 `tank.direction`。
   此时**先不加冷却**，故意感受一下"按住空格刷屏"是什么样。
3. **加冷却**：把刷屏治住。这一步做完，需求文档的验收标志就齐了。
4. **四个方向各测一遍**：上/下/左/右移动后各打一发，确认子弹都朝对应方向飞。
5. **调手感**：子弹速度、大小、颜色、冷却时长。

> **本条不做「飞出屏幕就销毁」** —— 那是**条目 7** 的内容。
> 所以现在子弹飞出屏幕后**仍然留在列表里**（看不见，但每帧还在更新和绘制）。
> 打几百发之后列表会变长，帧率可能略降 —— **这是预期的，不是你写错了**。
> 如果你觉得别扭，可以顺手把出屏销毁也做了（那就是条目 6+7 一起完成，分两次 commit 即可）。

## 7. 常见坑（按踩中概率排序）

1. **`bullets = []` 写在主循环里** → 每帧被重置，屏幕上永远只有一颗子弹（或者一颗都没有）。**列表必须定义在循环外。**
2. **以为"只在 KEYDOWN 里发射就不会连发"** → 错。**按住不放时操作系统会重复发 KEYDOWN**（约 30 次/秒），必须有冷却。
3. **方向搞反**：`"UP"` 写成 `(0, 1)` → 子弹朝反方向飞。y 轴向下，向上是 `-1`。
4. **子弹从坦克正中心出生** → 看起来从坦克肚子里冒出来，不像炮口。从朝向那一侧的边缘出生。
5. **冷却用帧计数却不换算** → `cooldown = 30` 在 60 FPS 下是 0.5 秒，但掉到 30 FPS 就变成 1 秒，手感飘。**用毫秒时间戳最稳。**
6. **`last_shot` 忘了初始化** → 第一发要么发不出来（`NameError`），要么一开局就能连发（初值给 0 时 `now - 0` 很大，第一发必然通过 —— 这其实是好事）。
7. **子弹速度设成 1 或 2** → 看起来像坦克在吐口水。坦克 5，子弹至少 10。
8. **画在坦克之前** → 子弹从坦克身上飞过时被坦克盖住，像"钻进坦克里"。顺序：**背景 → 地图 → 坦克 → 子弹**。
9. **`Bullet` 类里用了 `self.rect.x += ...` 却忘了 `update()` 每帧调用** → 子弹不动。检查主循环里有没有遍历更新。
10. **提前剧透**：条目 7 要"飞出屏幕就销毁"，那时你会想在 `for b in bullets:` 里 `bullets.remove(b)` ——
    **在遍历列表的同时删元素会漏掉元素**（甚至报错）。正确做法是**倒着遍历**，或者**用新列表收集存活的**。
    现在先记住这个坑，到条目 7 会用上。
