## 3. 核心概念：`MAP_DATA` 从「只读数据」变成「游戏状态」

到现在为止，`MAP_DATA` 是个**常量** —— 你只在 `draw_map()` 里读它，从没改过。画面上有没有墙，全看它。

本条目要做的事情，本质上是这一行：

```python
MAP_DATA[row][col] = 0        # 砖墙被打掉 → 数据里改掉 → 下一帧画面自然就没有它了
```

**注意这里没有"删除一个墙对象"这回事** —— 墙不是对象，它**只是二维列表里的一个数字**。你改数字，画面跟着变（这正是条目 5 建立的那个"数据驱动画面"思路的回报）。

**这个转折的意义**：
- 从今往后，`MAP_DATA` 是**可变的游戏状态**，不再是配置
- 以后做"多关卡"就是换一份初始数据；做"存档"就是把这个二维列表写进文件（需求文档 §5.2 的迭代项）
- 但也要小心：**它一旦被改，就不会自己恢复** —— 重开一局必须重新加载原始地图（条目 13 会踩到这个）

## 4. 三个碰撞场景

| 场景 | 结果 | 要改什么 |
|---|---|---|
| 子弹 × 砖墙（`1`） | **墙块消失**，子弹消失 | `MAP_DATA[row][col] = 0` + 移除子弹 |
| 子弹 × 钢墙（`2`） | **墙不动**，子弹消失 | 只移除子弹 |
| 坦克 × 墙（`1` 或 `2`） | 坦克**走不动**（回退本次位移） | 把坦克位置还原 |

### 4.1 关键：像素坐标 ↔ 格子下标

这是本条的**技术核心**，也是唯一容易算错的地方。你有一个像素矩形，要问"它压在哪些格子上"：

```
列号 = 像素 x ÷ 40        行号 = 像素 y ÷ 40
```

但**边界必须用 `right - 1` / `bottom - 1`**，否则会多算一格。我用实测给你看：

```
矩形 x=360..400（正好占满第 9 格 [360,400)）
  用 right // 40      -> 列 [9, 10]   ← 多算了第 10 格！
  用 (right-1) // 40  -> 列 [9]       ← 正确
```

**原因**：`Rect.right` 是**开区间**的右端点（`right = x + width`）。`x=360, width=40` 时 `right=400`，而第 10 格的范围恰好是 `[400, 440)` —— 那个 400 **不属于**这个矩形。

所以遍历一个矩形覆盖的格子，标准写法是：

```
列：rect.left // TILE  到  (rect.right - 1) // TILE
行：rect.top  // TILE  到  (rect.bottom - 1) // TILE
```

### 4.2 ⚠️ 负坐标陷阱（会静默取到错误的格子）

Python 的整除是**向下取整**，不是向零取整：

```
-1 // 40  =  -1        （不是 0！）
-41 // 40 =  -2
```

而 `MAP_DATA[-1]` **不报错** —— 它会取到**最后一行**！所以如果坦克或子弹跑到屏幕外（比如 x=-6），你不加检查就取 `MAP_DATA[row][col]`，会**静默命中错误的墙**，表现为"子弹在屏幕外莫名其妙打掉了一块墙"。

**对策**：取格子前先判范围：

```
if 0 <= row < len(MAP_DATA) and 0 <= col < len(MAP_DATA[row]):
    再读 MAP_DATA[row][col]
```

### 4.3 坦克会横跨两格（实测数据）

坦克 40×40、格子也是 40，但**只有位置正好对齐时才占一格**：

```
坦克 left=360  -> 覆盖列 [9]        （正好对齐）
坦克 left=365  -> 覆盖列 [9, 10]    （跨两格！）
坦克 left=370  -> 覆盖列 [9, 10]
```

你的 `speed = 5`，所以移动过程中**大部分时间都跨两格**。这意味着碰撞检测**不能只查一个格子**，必须查它覆盖的**所有**格子。

## 5. 实现顺序（每步都留一个能跑的状态）

1. **先写"像素 → 格子列表"的小工具函数**：给一个 `Rect`，返回它覆盖的所有 `(row, col)`。
   先拿它打印验证（坦克放在 `360,280` 时应该只有 1 格；`365,280` 时是 2 格）。
2. **做坦克撞墙**：移动前记下旧位置 → 移动 → 检查覆盖格里有没有墙 → 有就还原位置。
   这一步做完，"坦克穿墙"就治好了。
3. **做子弹打墙**：每颗子弹检测它覆盖的格子。命中 `1` 就改成 `0` 并删子弹；命中 `2` 就只删子弹。
4. **调整更新顺序**：子弹的"移动 → 碰墙检测 → 出界清理"应该连着做，别散在几处。
5. **自测**：朝砖墙打（墙消失）、朝钢墙打（墙还在）、把坦克往墙上怼（走不动）。

> **建议**：碰撞逻辑写成**独立函数**，不要塞进 `Tank` 或 `Bullet` 类里。
> 理由：碰撞涉及"子弹 + 地图"两个东西，**不属于任何一方**。
> 条目 14 拆模块时，它会自然归到 `map.py` 或单独的 `collision.py`。

## 6. 验收标准（逐条打勾）

| # | 验收项 | 怎么验 | 期望结果 |
|---|---|---|---|
| 1 | **坦克撞墙走不动** | 把坦克开到墙边，继续朝墙按方向键 | 坦克**贴住墙停住**，不穿过去、不抖动、不卡死 ← **需求文档硬指标** |
| 2 | **子弹打砖墙，墙块消失** | 朝砖墙打一发 | 那一块砖墙**消失**，子弹也消失 ← **需求文档硬指标** |
| 3 | 子弹打钢墙被挡住 | 朝钢墙打一发 | 子弹消失，**钢墙还在** |
| 4 | 墙消失后能通过 | 打掉一块砖墙后开过去 | 坦克能穿过那个缺口 |
| 5 | 一枪只打掉一块 | 朝砖墙打一发 | 只有**正对的那一块**消失，旁边的不受影响 |
| 6 | 坦克能沿墙滑动 | 斜向/侧向贴着墙走 | 沿墙方向能正常移动（不是完全卡死） |
| 7 | 不穿墙（高速也不行） | 贴着墙反复撞 | 任何速度下都不穿墙 |
| 8 | 子弹不出屏外打墙 | 贴边开火 | 不会在屏幕外"隔空"打掉墙 |
| 9 | 帧率稳定 | 探针 | 稳态仍在 60 附近 |
| 10 | 干净退出 | 点 × | 退出码 `0` |
| 11 | **Git 动作** | `git branch --show-current` | 在 `feature/collision` 上，已 push |
| 12 | 已提交 | `git log --oneline` | 新增 commit，信息形如 `feat: 子弹打墙与坦克撞墙的碰撞检测` |

> **第 1、2、3、5、8 条我会用探针实测**（这次探针会直接改 `MAP_DATA` 来造场景，比手动摆位置可靠）：
> ① 把坦克摆在墙边持续推，逐帧记录位置 → 确认它**停住且不穿墙**；
> ② 朝砖墙开火 → 对比开火前后 `MAP_DATA` 里 `1` 的个数**少 1**、且消失的正是正对那格；
> ③ 朝钢墙开火 → `2` 的个数**不变**、子弹消失；
> ④ 把坦克放到屏幕左边界朝左开火 → 确认**没有墙被隔空打掉**（验 4.2 那个负索引陷阱）。

## 7. 常见坑（按踩中概率排序）

1. **⚠️ 用 `right // 40` 而不是 `(right-1) // 40`** → 矩形正好贴格线时会**多算一格**，表现为"打一枪掉两块墙"（打中目标格 + 右边/下面那格）。
2. **⚠️ 不检查下标范围** → 负坐标经 `//` 变成负数下标，`MAP_DATA[-1]` **静默取到最后一行**，在屏幕外打掉墙。**这个 bug 不报错，极难发现。**
3. **只检测一个格子**（用 `rect.centerx // 40`）→ 坦克跨两格时漏判，表现为"有时候能穿墙"。
4. **坦克撞墙后没回退，而是把速度设 0** → 松手前一直"贴着"，但一旦换方向再按回来还是会穿。**回退位置**才是干净的做法。
5. **回退时把 `direction` 也一起还原** → 坦克撞墙后朝向不更新，表现为"按了上键但炮口还朝右"。**只回退位置，不回退朝向**（原地转向是合理的）。
6. **子弹先判出界再判撞墙** → 贴边开火时子弹已被销毁，撞墙检测永远不执行。顺序建议：**移动 → 撞墙 → 出界**。
7. **打掉墙后忘了删子弹** → 一颗子弹连穿好几块砖墙（除非你就想要穿透效果，那要明说）。
8. **改 `MAP_DATA` 时用错下标顺序**（`[col][row]`）→ 墙消失的位置"镜像"了。记住是 `[行][列]`。
9. **一帧内同一颗子弹打掉多块墙** → 检测到第一块后就该 `break`（子弹已经没了，没必要继续）。
10. **性能**：子弹只有几颗、地图只有 300 格，随便怎么写都不卡。**不要为性能写复杂代码**（比如四叉树），那要到几千个对象才需要考虑。
11. **进阶（本条不做）**：子弹速度如果大于格子宽度（40），可能**一帧跨过整格**导致"隧穿"。你现在速度是 10，**不会**发生。知道有这么回事就行。
